# Rclone Browser Next 0.6.0：介面驗證

## 正式結果

**2026-10-20 的完整介面測試為 140／140 通過，0 失敗、0 略過、0 flaky。** 開始時間為 UTC 12:10:08.621，耗時 165.7 秒。TypeScript 型別檢查與 Vite 正式建置均通過。

測試直接以 `file://` 載入交付用的 `Resources/Web/index.html`、JavaScript 與 CSS。原生 host 由測試專用 fixture 回應，因此可以核對真正的橋接方法、參數、回覆與事件，但不會連接使用者帳號。正式資源沒有包含 fixture 或示例檔案系統。

140 個案例包含原有 86 項、第一批 0.6 的 26 項，以及追加需求的 28 項。全部在同一次完整執行中通過；不把開發期間重跑的案例加入總數。完整執行與最後 32 張預覽之間，正式產品檔案保持不變。[verification.json](verification.json) 保存執行數字、正式檔案 SHA-256、預覽雜湊、色彩及字型證據。

### 六個常用方案

| 方案 | 同時傳輸 | 同時檢查 | 單檔平行分段 |
| --- | ---: | ---: | --- |
| 本機 → 本機 | 1 | 10 | 關閉 |
| 本機 → NAS | 1 | 10 | 關閉 |
| 雲端 → 本機／NAS | 1 | 10 | 關閉 |
| 本機 → 雲端 | 7 | 10 | 使用後端預設 |
| NAS → 雲端 | 7 | 10 | 使用後端預設 |
| 雲端 → 雲端 | 7 | 10 | 使用後端預設 |

所有方案都設定為以來源為準的單向同步，預設大小與修改時間、不計算本機雜湊，傳輸時刪除，刪除數量不限。套用時重設這次的完整選項、清除會保留差異的略過規則，但不改動兩側位置、不自動啟動。六個方案皆可隱藏並復原。

比對說明區分「避免為算雜湊而讀回 NAS 內容」與「實際變更資料仍經過執行 rclone 的 Mac」。不計算本機雜湊不能保證內容完整校驗；大小與修改時間都沒變的內容修改仍可能漏判。減少傳輸數也不保證檔案連續存放。

修改時間容差說明配合 Core：空白時檢查實際本機卷格式，已知 FAT 用 2 秒、HFS 用 1 秒、exFAT 用 10 毫秒；APFS、SMB 掛載及未知格式維持 rclone 判斷，手動設定優先。實際偵測與套用內容由指令預覽及工作紀錄呈現。本報告只驗證介面說明與傳遞設定，磁碟格式偵測由 Core 測試。

### 返回／前進與側鍵

DOM fallback 不再因一個全域旗標而整體關閉。原生事件的 epoch 時間與 DOM mousedown 時間用最近的尚未配對手勢比對，只去除同一次實體操作的重複事件，不做方向節流。

通過的情境包含原生先到、DOM 先到、DOM 已導航後原生才到、快速連按、mouseup 後的 auxclick、只有 auxclick 的驅動行為，以及 BrowserBack／BrowserForward、Alt 左右鍵、Cmd／Ctrl 方括號。各分頁仍有獨立的返回／前進歷史；有對話框時不導航，編輯欄位保留文字快捷鍵。實體滑鼠與原生縮放座標的測試由 Mac host 套件另行記錄。

## 逐檔紀錄與數字意義

工作摘要分開顯示需傳輸、已傳輸、已檢查、略過紀錄及錯誤次數。Checks 不被當成略過數，錯誤紀錄也不被宣稱為最後失敗的唯一檔案數。

| 資料 | 介面呈現與限制 |
| --- | --- |
| `transfers / totalTransfers` | 已傳輸與目前已發現的傳輸總數。總數包含完成、排隊與傳輸中，會因掃描、失敗或重試改變；不是固定來源檔案總數。 |
| `checks / totalChecks` | 獨立顯示已檢查與目前檢查總數，可能包含不同階段或重試。 |
| `matchedEvents + skippedEvents` | 「略過紀錄」的事件次數；同一路徑重試可能出現多次。也可能由略過既有／較新目標規則決定，不表示內容已完整驗證相同。 |
| `stats.errors` | 主摘要的 rclone 錯誤次數，不能推算唯一失敗檔案。重試仍可能成功。 |
| 錯誤分類 | 包含 JSON 錯誤與 comparison-error 訊號，分別標示檔案路徑或一般錯誤。比較錯誤訊號不一定是最終傳輸失敗。 |
| 舊工作 | 沒有 ledger 時顯示沒有逐檔紀錄，略過數保持未知，不從 Checks 反推。 |
| Dry Run | 顯示預演標記、估計資料量與「預演處理」，不把模擬統計寫成真的上傳完成。 |

展開詳細資料後，依需要載入「全部、比對、略過、已完成、錯誤」分類，每頁最多 **100 筆**。下一頁使用不透明 byte offset，畫面不一次掛上全部紀錄。列內保留時間、動作、路徑及訊息；原始錯誤不翻譯，App 自己產生的比較說明會隨繁／英／日文即時切換。

`getJobReport` 只在展開、換頁／分類或按重新整理時請求，不跟著每秒進度去拉取。手動刷新可使用比 `job.report` 更新的 writer 摘要。有新事件時先提示可刷新，刷新後清除提示。無法辨識的比較訊息會顯示警告，並提供原始比對匯出；完整 JSONL、原始 rclone log 與指令仍可取得。

測試包含空報告、legacy、讀取失敗／重試、malformed 提示、完整匯出與原始比對匯出、分頁游標、三語最小視窗、一般錯誤與檔案錯誤、重試事件語意，以及含換行／HTML 字串的檔名。可疑字串只作為文字呈現，不形成可執行標記。

## 負擔檢查

兩側各有 **100,000 筆虛構檔案**時，兩側合計渲染列數少於 100。25 個進度更新沒有再對整份清單執行 `map`、`filter` 或 `sort`，也沒有多發出目錄列表請求；觀察時間為 **626.2 ms**。

報告另驗證 100 筆頁面在連續進度事件期間沒有多次查詢，分類與換頁才載入需要的資料。這些是防止重複清單工作與無謂輪詢的回歸檢查，不能當成某台 Mac 的 CPU 百分比或某台 NAS 的滿速測試。

## 六色與預覽

**120／120** 個指定色對通過：一般文字最低 **4.90:1**，控制項邊界最低 **3.50:1**。檢查包含文字、次要資訊、placeholder、主按鈕狀態、選取文字、提示訊息與邊界；停用控制項不列入，這不是完整無障礙稽核。

綠色介面採低飽和衍生色：淺色重點 `#366249`、淺色選取底 `#E5EEE8`、深色重點 `#A8C8B1`。來源是提供色卡中的綠階方向，沒有直接把圖表的大面積填色套在整個視窗背景。

最後 **32 張** 預覽都從這份通過測試的正式資源產生，包括六主題、繁中／英文首頁、實際可見的浮動通知、六方案選單、逐檔摘要／比對／錯誤，以及 125% 的設定、傳輸、作業和報告介面。截圖前移開游標，報告頁同時只有一個 `aria-pressed=true` 的分類。

兩份 README 主圖使用一致的虛構場景：4／16 已傳、4 筆成功紀錄、12 筆略過紀錄、256 MiB／1 GiB、16 MiB/s、預估剩餘 48 秒；錯誤示例另外加入兩筆錯誤並將錯誤次數設為 2。所有檔案、遠端、帳號和路徑都是測試資料，沒有公開使用者截圖內容。正式 README 圖為 `docs/images/main-dark.png` 與 `main-dark-en.png`。

字型檢查實際渲染來源為繁中 Noto Sans CJK TC、英文 DejaVu Sans，路徑使用 DejaVu Sans Mono，沒有 Times fallback。這些 Linux 預覽沒有包裝成原生 Mac 截圖；Mac 仍使用系統字型。
