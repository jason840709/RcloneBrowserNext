# Rclone Browser Next 使用手冊

作者：**Jason Chen**

Rclone Browser Next 是給 macOS 使用的雙面板 rclone 圖形介面。左右兩邊都能選本機資料夾、雲端或 NAS／伺服器，依指定方向複製、移動或同步。

[專案首頁](README.md) · [English](README.en.md) · [Mac 建置說明](docs/BUILD_MAC.zh-TW.md) · [功能對照](docs/FEATURE_MATRIX.zh-TW.md) · [修改記錄](docs/CHANGELOG.zh-TW.md)

另提供 Windows／Linux [相容版安裝包](docs/BUILD_COMPATIBILITY.md)。以下原生操作以 Mac 版為主，共用的傳輸設定與報告適用於三個平台。

## 開始使用

需要 **macOS 13 以上**，支援 Apple Silicon 與 Intel。

1. 解壓縮完整來源包，保留資料夾內的檔案結構。
2. 雙擊 `Build-on-Mac.command`。完成後，同一個資料夾會出現 `Rclone Browser Next.app`。
3. 開啟設定，選擇 **rclone 安裝位置**。資料夾中應有名為 `rclone` 的執行檔，也可直接選擇既有的執行檔。
4. 要新增雲端或 NAS 帳號，點左上角 **帳號設定（Config）**，依 rclone 的互動提示完成設定。
5. 在左右面板選擇位置，確認傳輸方向與操作，先做 **Dry Run** 查看結果，再開始傳輸。

建置使用 Mac 已有的 Apple 開發工具。一般建置不下載套件、不安裝 Homebrew、Node.js 或 rclone；編譯快取、暫存、記錄與產物都放在這個專案資料夾中。若尚未安裝 Apple Command Line Tools，腳本會說明缺少的工具並停止。

rclone 與 App 分開存放。沒有安裝 rclone 時，仍能開啟 App 設定位置；本機資料夾可直接瀏覽；遠端瀏覽與 rclone 傳輸等操作要等引擎可用。

從舊版升級時，先結束正在執行的 App，再把新版完整解壓縮到新的資料夾並建置。新版沿用原本的設定與儲存作業；外部 rclone 保留在原來的安裝位置，不需要重新下載。請勿把新舊版本的來源檔案混在同一個資料夾。

## 這版的操作方式

### 選擇位置

位置選單固定在圖示下方開啟。長清單可捲動，使用鍵盤移到後面的選項也只捲動清單，位置列維持原位。

左右面板各自選擇位置，來源與目標可以是本機、本機掛載的網路磁碟、雲端或 rclone remote。

位置選單提供常用 Mac 資料夾：個人資料夾、桌面、文件、下載項目、圖片、音樂、影片，以及目前掛載的磁碟。路徑由系統讀取，不固定使用者名稱。Cloud 與 NAS／伺服器按後端類型分組；WebDAV 等可能有多種用途的連線會保留明確的協定名稱。

檔案表格支援調整欄寬；縮窄欄位後，列底色仍延伸到面板邊緣。修改日期包含西元年。六個主題使用灰白或深灰底色，紫色、藍色、低飽和綠色用於選取、焦點與主要操作。預設為深紫主題。

每個面板依序顯示左右與來源／目標標示、資料夾分頁，以及合併的位置／路徑導覽列。選中的分頁與內容區塊使用相同底色。返回、前進、上一層各有按鈕；滑鼠側鍵或 Command＋`[`／`]` 可切換該分頁的瀏覽歷史。滑鼠停在另一側時，側鍵操作該側；不會把整個 App 當成網頁返回。

讀取失敗時，圖示、標題、錯誤內容與重試按鈕放在同一張提示卡片中。作業尚未建立時，只顯示新增提示。儲存等短暫通知懸浮在畫面上，不擠動原本版面，可關閉或約 5 秒後自行收起，並遵循系統減少動態效果設定。

### 複製、移動、同步與 Dry Run

| 操作 | 行為 |
|---|---|
| 複製 Copy | 將符合條件的來源檔案傳到目標，保留來源；不因來源缺少檔案而刪除目標 |
| 移動 Move | 傳送成功，或目標已有依本次設定無需更新的副本時，移除來源檔案 |
| 同步 Sync | **以來源為準，只修改目標。** 更新目標檔案，刪除目標中來源已沒有的檔案；不反向修改來源 |
| Dry Run | 用目前設定執行 rclone 預演，列出預計動作，不實際複製、移動或刪除檔案 |

Dry Run 仍會列目錄、讀取必要的比較資訊並產生日誌；若選擇需要內容雜湊的比較方式，也可能讀取檔案內容。預演後到正式執行前，來源或目標若變動，實際結果也會跟著改變。

移動、同步與刪除會先顯示原生確認視窗。按 Command＋Q 每次都會詢問；有工作時，會說明結束將停止傳輸、掛載或播放。已完成的檔案變更不會因退出而復原。

同步使用 rclone 的單向 `sync`。選取範圍、排除規則及比較方式仍會影響哪些檔案被處理；預設保留目標中被排除的檔案。若開啟略過已存在或略過較新的檔案，目標也可能保留與來源不同的版本。這些都是明確選擇的例外，不是雙向同步或自動取兩邊較新版本。[rclone 同步說明](https://rclone.org/commands/rclone_sync/)

### 常用備份方案

操作方式選單的前段提供六種方案，後段保留複製、同步、移動。選方案會套用傳輸選項，不改變目前左右位置，也不直接開始工作；請確認來源、目標與方向後，再預演或執行。

| 方案 | 同時傳輸／檢查檔案數 | 主要設定 |
|---|---|---|
| 本機 → 本機 | 1／10 | 適合另一顆本機或外接磁碟；停用單一檔案多路並行 |
| 本機 → NAS | 1／10 | 減少對 NAS 的同時寫入；停用單一檔案多路並行 |
| NAS → 雲端 | 7／10 | 允許多檔上傳 |
| 本機 → 雲端 | 7／10 | 允許多檔上傳 |
| 雲端 → 雲端 | 7／10 | 允許多檔傳輸；資料路徑仍由服務端能力決定 |
| 雲端 → 本機／NAS | 1／10 | 減少對磁碟的同時寫入；停用單一檔案多路並行 |

六個方案都採用**單向同步、大小與修改時間／不計算本機雜湊、傳輸時刪除、不限刪除數**。它們是可調整的起點，不保證適合每台裝置的最高速設定；單檔傳輸減少平行 I/O，不能保證磁碟連續配置。方案左側的 × 只會隱藏該入口，傳輸選項中的還原按鈕可以重新顯示。

方案會排除 `.DS_Store`、`._*`、`.Spotlight-V100`、`.Trashes`、`.fseventsd`、`.TemporaryItems` 等指定項目，不會排除全部隱藏檔。`._*` 可能包含 Mac 資源分支或延伸資料；需要保留時，請刪除該條排除規則。這是一般檔案備份，不是完整系統映像。

**已儲存作業及記住的工作環境保留原本選項**，不會因新版方案改變傳輸數或放寬刪除上限。要讓舊作業採用新方案，請編輯並重新儲存。

### 選取部分資料夾

只有來源端顯示勾選框。沒有勾選時，處理整個目前資料夾；勾選後，處理選取的來源項目，放進目標的同名路徑。目標端的單列焦點可用於重新命名等檔案操作，不是傳輸範圍。

同步可選取一個或多個**資料夾**：例如選取 `Photos` 與 `Documents`，只同步到目標的 `Photos` 與 `Documents`，其他目標資料夾不會被刪除或改寫。同步時不能混選個別檔案，也不能啟用「刪除已排除的檔案」。個別檔案可使用複製或移動。ⓘ 會顯示這次選取的處理方式。

若同時設定包含規則，只處理「選取範圍」與「規則」都符合的檔案；這個組合會在開始前列出兩側相關檔名，讓只存在於目標、但在同步範圍內的舊檔也能正確刪除。它不讀取檔案內容計算雜湊。

切換傳輸方向或交換左右位置時，會清除各分頁的舊勾選，避免把原目標的選取誤當成新來源。套用已儲存作業或 Finder 拖放時，只還原明確指定的新來源選取。

### 外接磁碟的修改時間精度

「時間容許誤差」留白時，App 會查詢實際本機卷的檔案系統。FAT、HFS 與 exFAT 的時間精度不同；App 會依已知格式採用相應容差，來源與目標取較大的值，並在指令預覽及紀錄中說明。沒有建立測試檔案，也不會將自動值寫回作業設定。

APFS、未知格式與 Finder 掛載的 SMB 磁碟不會被一律套用較寬容差；直接設定的 SMB 等遠端仍由 rclone 的後端判斷精度。手動指定容差時，以使用者的值為準。容差內、大小相同的內容修改可能無法辨識，因此不應任意放大數值來避免重傳。[比較方式與限制](docs/NAS_COMPARISON.zh-TW.md)

### 速度、剩餘時間與百分比

傳輸中，以最近 60 秒的已處理容量變化估算平均速度；剛開始未滿 60 秒時，用已經過的時間。完成後保留整次工作的平均速度。百分比顯示一位小數，數量欄標為「檔案數量」。

估算只使用既有的每秒 rclone 統計，不另外掃描、讀取或雜湊檔案。macOS 系統快速複製可能只有容量資料而沒有 rclone 原生速度，這個方法也能顯示進展；該數值代表處理容量，遇到 APFS 或伺服器端複製時不等於網路流量。尚未回報進度、長時間沒有容量變化或總量未知時，剩餘時間會顯示尚無法估計。

剩餘時間是粗估。大量小檔、刪除／檢查階段，以及尚未列舉完成的目錄，都可能讓估計繼續變動。設計依據見 [統計與 NAS 行為查核](docs/RESEARCH_0.5.0.md)。

### 檔案數量與逐檔報告

工作摘要把容量與檔案數分開，並顯示不同階段的數字：

| 欄位 | 如何理解 |
|---|---|
| 需傳輸 | rclone 目前已發現需要傳輸的檔案數；目錄尚未掃描完時可能增加 |
| 已傳輸 | rclone 回報的完成數；Dry Run 會改標示為預演數字 |
| 已檢查 Checks | 已檢查／目前預計檢查的數量；不能直接當成略過數 |
| 略過紀錄 | 依比對或選項略過的事件，包含符號連結與特殊檔案 |
| 錯誤 | rclone 回報的錯誤次數；同一檔案重試可能產生多次錯誤 |

「詳細資料與紀錄」提供**全部、比對、略過、已完成、錯誤**分頁。每筆列出時間、檔名、動作及訊息；沒有指定檔案的連線或一般錯誤會另外標示。完成分頁也可能包含成功的刪除或移動等動作，請依動作標籤判讀。

比對結果與執行結果分開保存。例如「目標缺少檔案」表示需要處理，還不是複製成功；「依規則略過」也不一定表示做過內容雜湊驗證。同一檔案可能先失敗、重試後成功，所以分頁的紀錄筆數不等於不重複檔案數，也不等於最終仍失敗的檔案數。

畫面分頁讀取紀錄，完整的逐檔報告可匯出為 JSONL，原始比對輸出另可匯出為文字檔；傳輸途中匯出的是當下的固定快照。原有的 rclone 原始紀錄與執行指令仍保留。新報告沿用這次工作的輸出，不額外掃描來源、讀取 NAS 檔案或啟用全量除錯日誌。

原始比對輸出是 rclone 的行式格式；特殊檔名與少數服務端操作有格式或回報限制，無法解析時會提示，並保留原始輸出供查閱。舊版工作不會憑空補出當時沒有記錄的逐檔資料。成功工作在下次啟動時會自動清除，需要長期保留報告時請先匯出。

### 記住目前設定

點左上角 **記住**，會保存左右位置、傳輸方向、操作方式與全部傳輸選項。下次開啟 App 時還原這個工作環境，讓你接著操作；**不會自動執行傳輸**。

記住的環境不保留檔案勾選；要保留選取範圍，請儲存成 Task。

「預設啟動資料夾」適合指定固定起點；「記住」則同時保存當前兩側位置和傳輸設定。

### 傳輸工作佇列

傳輸成功後，工作會顯示綠色「已完成」，可在本次使用期間查看結果。下次開啟 App 時，會自動移除這些成功紀錄；失敗、取消或中斷的工作仍保留，方便確認與重試。上次尚未完成的工作不會自行開始傳輸；儲存的 Tasks 也不受這項清理影響。

垃圾桶會依所在分頁處理：

| 所在分頁 | 按下垃圾桶後 |
|---|---|
| 已結束 | 清除該分頁的紀錄，包括成功、失敗、取消及中斷；不影響進行中的工作 |
| 全部／進行中，且仍有工作在跑或排隊 | 詢問要「終止進行中並清除」，或「只清除已完成」；也可以取消 |
| 全部，且沒有進行中的工作 | 清除列表中的已結束紀錄 |

「只清除已完成」只清除綠色成功紀錄，會保留失敗與中斷。「終止進行中並清除」作用於按下垃圾桶時該分頁中的工作；對話框開啟後新建的工作不包含在內。

停止傳輸時，App 先要求 rclone 正常收尾，顯示「正在停止」，等程序確實結束後再更新狀態。已完成的檔案變更不會復原；App 不會猜測或掃描刪除目標檔案。rclone 支援的一般本機／SMB 傳輸會使用暫存檔或服務端上傳工作階段，但不同目的端的清理能力不同，斷線或強制停止也可能留下未完成資料。需要升級為強制停止時會明確提示，請查看記錄與目標位置。詳細依據見 [停止與清理行為](docs/RESEARCH_0.6.0.md)。

### 儲存作業 Tasks

每個作業都有 **Dry Run、Run、Edit、Delete** 四個入口。儲存與編輯使用完整設定畫面，可以核對來源、目標、方向、複製／移動／同步、比較方式、略過條件、同步刪除時機、包含／排除規則、速度及其他傳輸參數。

編輯既有作業會更新同一個作業；另存新作業則建立副本。作業保留自己的傳輸選項，之後調整主畫面不會直接改寫它。執行時仍使用目前有效的 rclone、帳號設定檔與全域連線設定；作業內明確設定的逾時或額外參數可覆蓋對應預設。

## 設定

### rclone 安裝位置與更新

選擇資料夾就使用其中的 `rclone`。直接選擇執行檔時，同時以其父資料夾作為安裝位置，不需要再管理兩條互相競爭的路徑。

選完位置立即儲存、探測版本並刷新。更新會在目前指定的位置下載、驗證與替換；失敗時保留或還原舊版。引擎更新可在啟動時檢查，也可手動檢查，並支援稍後處理或跳過某個版本。

App 選單中有兩項更新：

- **檢查 rclone 更新**：檢查外部引擎，經確認後更新指定位置中的 rclone。
- **檢查 Rclone Next 更新**：檢查本專案的 GitHub 正式版本，提供新版下載頁與更新說明。這個入口不會直接覆寫正在執行的 App。

公開專案位於 [jason840709/RcloneBrowserNext](https://github.com/jason840709/RcloneBrowserNext)。App 更新讀取該專案的正式 Release；如果新版已公開，會提供下載頁。來源提交本身不等於正式 Release，實際可下載版本以 [Releases](https://github.com/jason840709/RcloneBrowserNext/releases) 為準。外部 rclone 的更新功能獨立運作。

### 外觀與語言

外觀變更立即套用，提供深紫、淺紫、深藍、淺藍、深綠、淺綠。主畫面、載入畫面、執行中的 Dock 與選單列圖示跟著紫／藍／綠色系切換。Finder 與 App 結束後的 Dock 使用固定的紫色圖示。三色圖示素材均保留透明背景與三圈造型。

介面大小提供 **80%、90%、100%、110%、125%** 五段，預設是中間的 **100%**。文字、圖示、按鈕和間距一起縮放，選完立即套用並記住；macOS 自己的選單、檔案選擇視窗與系統確認框仍遵循系統顯示設定。

語言可選繁體中文、English、日本語或「預設（跟隨系統）」。跟隨系統時，以主要系統語言判斷：中文使用繁體中文，日文使用日本語，其他語言使用 English。

### 同時工作的數量

預設 **不限制同時工作的數量**，與原版直接啟動工作的方式一致。需要控制資源時，可以自行指定工作上限；這與單一工作內的「平行傳輸數」「平行檢查數」是不同層次。

0.3 的預設上限 2 會在升級時解除；先前另設的非預設數值會保留。0.4 之後明確選擇 2，會正常記住。成功、失敗、取消的歷史紀錄合計最多保留最近 200 筆；重新啟動時會再移除其中成功完成的紀錄。中斷後尚未完成的工作保留到手動清除，不納入自動淘汰；執行中與排隊中的工作、另存的 Tasks 也不受這個歷史筆數影響。

### 網路

代理可沿用啟動環境，或指定 HTTP／HTTPS／SOCKS 代理與例外位址。rclone 連線另可設定 IPv4／IPv6、來源 IP、連線逾時、傳輸閒置逾時、每秒請求數、瞬間請求上限、User-Agent 與停用 HTTP/2。

App 和引擎的更新下載支援系統代理、手動 HTTP CONNECT 與 SOCKS5。若手動代理位址本身是 `https://`，更新檢查會提示改用 `http://` 或 `socks5://`；這是目前原生更新連線的限制，rclone 傳輸仍可使用 `https://` 代理。

「來源 IP」是這台 Mac 可用的位址，不是 `en0` 之類的網卡名稱。每秒請求數用來降低 API 呼叫頻率，不等於傳輸速度限制；傳輸速度在傳輸選項中設定。HTTP/2 選項主要供代理或伺服器相容性排查使用。更新檢查使用 HTTPS 與代理設定，rclone 專用的 TPS、來源 IP 等選項不會套用到 App 自己的更新請求。

## SMB／NAS 比較

Finder 掛載的 SMB 路徑，對 rclone 屬於本機檔案系統。計算這些檔案的雜湊，會經由網路讀取內容。

**大小與修改時間（不計算本機雜湊）** 適合以 SMB 掛載的 NAS：使用 metadata 判斷，停用 local backend 的內容雜湊，避免單純為比較而讀回目標整個檔案。它能利用修改時間辨識同大小的修改，但在這個 local 傳輸情境不提供內容雜湊校驗；大小與時間都沒變的內容修改仍可能漏掉。這個選項只停用本機後端的雜湊，不會停用所有雲端後端的雜湊能力。

「只比大小」更快，但會略過同大小的內容修改；「大小＋雜湊」較重視內容比較，可能增加讀取量。各選項旁的 ⓘ 說明會指出行為、適用情況與代價。詳見 [NAS 比較說明](docs/NAS_COMPARISON.zh-TW.md)。

NAS 傳到另一家雲端時，確定要更新的內容通常仍會經過執行 rclone 的 Mac。上述比較設定減少的是「為了比對而額外讀完整份檔案」的流量，不能讓不支援直接互傳的服務忽然直連。若要讓傳輸完全不經過 Mac，需要把傳輸程序放在 NAS 等其他主機執行。[rclone 跨服務傳輸說明](https://rclone.org/faq/#can-rclone-sync-directly-from-drive-to-s3)

## 為什麼體積小

這個 App 使用 Swift／AppKit，以及 macOS 內建的 WebKit，沒有在包內再放一份瀏覽器引擎或 Qt。rclone 也獨立安裝，因此 App 大小不包含 rclone。

來源 ZIP、解壓縮後的來源、編譯完成的 `.app`、外部 rclone 是四種不同大小，不能直接混在一起比較。建置腳本會列出你的 Mac 實際產生的 App 大小。功能完整性以功能對照、測試及實際使用結果判斷，檔案大小本身不代表功能是否完成。

## 簽章與驗證

在 Mac 建置完成後，腳本會對完整 App 建立本機簽章並驗證；可另執行 `Verify-App.command`。這不是 Apple Developer ID 簽章或公證，因此公開下載的 CI App 仍可能受到 Gatekeeper 限制。現階段建議使用來源包在自己的 Mac 建置。

測試方法與驗證範圍見 [驗證記錄](docs/VALIDATION.zh-TW.md)。來源內附的測試使用合成資料；不包含真實雲端帳號、使用者的檔案列表或參考截圖。

## 活動檔案與重試

報告會列出來源變動或大小驗證失敗的訊息；同一路徑多次失敗且大小持續增加時，會顯示來源增長提示。成功複製及失敗副本的大小依事件累計，同一路徑多次傳送會再次計入。完整備份程式資料夾，請先正常結束寫入程式，或採用一致性快照；詳見[活動檔案的備份說明](docs/RESEARCH_0.7.0.md)。

「符號連結」可選略過或保留。保留時儲存連結本身及指向路徑，雲端用 `.rclonelink` 檔案保存；下載時也選保留即可還原。
