# Rclone Browser Next 0.10.2

這一版整理傳輸進行中的速度、統計數字與錯誤提示，讓畫面上的數字和顏色都說得清楚「現在發生什麼事」。傳輸、比對與帳號設定的行為沒有改變。

## 傳輸速度只算真正在傳的時間

rclone 不會把不用傳、略過的檔案算進資料量，所以速度從來不會被它們灌高。真正的問題在另一頭：0.10.1 的速度看最近 10 秒，平均速度看整段工作時間，兩者都把 rclone 只在比對檔案、建立資料夾的時間也算進去，結果是把速度拉低。

- 現在速度只用 rclone 自己記錄的「至少有一個檔案在傳」的時間計算，等於 rclone 統計裡的 transferTime。
- rclone 只在比對檔案或建立資料夾時，速度欄顯示「檢查中」，不再顯示一個慢慢掉到 0 的數字；既沒有在比對也沒有在傳時，顯示「未在傳輸」。
- 剩餘時間在檢查期間沿用上一次的估計，不會消失。
- 工作結束後的平均速度同樣只算有在傳的時間，很長的比對階段不會讓工作看起來很慢。

傳到本機外接硬碟時，一開始的速度可能特別高：macOS 會先把寫入的資料收進記憶體，再慢慢寫到硬碟，rclone 看到的是資料交給系統的速度。這是 Finder 複製也有的現象，幾秒後就會回到硬碟的實際速度。

## 傳輸卡片的統計數字

原本第二排的「需傳輸檔案」「已傳輸」和第一排的「檔案數量」是同一組數字；「已檢查」常被讀成「確認過不用傳的檔案」，但 rclone 的檢查次數其實也包括在目標建立或核對資料夾；「略過紀錄」則把「內容相同所以不用傳」和「依設定不處理」（例如捷徑）混在一起。

- 第一排：已傳資料量、已傳檔案、速度、剩餘時間。
- 第二排改成檔案的去向：不用傳（兩邊已相同）、已略過、已刪除（只在同步時顯示）、錯誤次數。
- 「檢查次數」移到「詳細資料與紀錄」，說明它包含資料夾，不等於不用傳的檔案數。
- 每個數字的滑鼠提示都改寫成不需要 rclone 知識也看得懂的說明。

## 錯誤改成小燈號，並翻成白話

0.10.1 只要 rclone 回報任何錯誤，就把原文用大片紅框顯示，即使 rclone 之後會自己重試成功。實際例子是 Google Drive 回報「每分鐘請求次數超過上限」：這是 rclone 共用的 Google 應用程式 ID 被所有使用者用到額度上限，rclone 會自動放慢並重試，檔案沒有問題。

- 錯誤改成一行：一顆小燈加一句白話標題，例如「雲端暫時限流，會自動重試」。完整說明與原始錯誤訊息收在「說明」裡。
- 橘燈：rclone 會自己處理，例如限流、網路不穩、雲端服務暫時出錯。工作進行中時燈會慢慢閃。
- 紅燈：需要使用者處理，例如沒有權限、檔名太長，或工作失敗。
- 只有整個工作都無法繼續的情況（雲端空間已滿、目標磁碟已滿、帳號登入過期）會自動展開說明。
- 認得的錯誤類型：限流、雲端空間已滿、本機磁碟已滿、登入過期、沒有權限、檔名太長、檔名含不支援的字元、找不到檔案、內容核對不一致、網路中斷或逾時、雲端服務暫時故障。逐檔紀錄裡的錯誤也用同一套說明。
- 讀取資料夾清單失敗這類錯誤沒有對應到特定檔案，所以不會出現在逐檔紀錄的「錯誤」分頁；提示會說明這一點，不再出現「上面說有錯、下面錯誤 0 筆」卻沒有解釋的情況。
- 工作最後成功時，代表過程中的錯誤已在重試後解決：不顯示燈號，錯誤次數改成一般的灰字，畫面和沒出錯的工作一樣。

使用 rclone 共用 Google 應用程式 ID 的帳號，rclone 會警告這個共用 ID 將在 2026 年內停用。建議依 [rclone 的說明](https://rclone.org/drive/#making-your-own-client-id) 建立自己的 client_id；限流也會因此少很多。

## 其他

- 同步與移動的確認視窗裡，「開始同步」「開始移動」改回一般按鈕。開始傳輸是使用者要做的事，不是錯誤；預設按鈕仍是「取消」，刪除範圍也照樣寫在說明裡。
- Windows 安裝版加入「從 0.10.1 升級」的驗證。

## 驗證

- 原生測試全部通過，新增「速度只算傳輸時間；比對與建立資料夾時顯示檢查中」的測試。
- 新增介面測試：限流是橘燈且說明收起；磁碟已滿是紅燈且自動展開；重試後成功結束的工作沒有燈號與紅字；只在比對時速度欄顯示「檢查中」。
- 在開發版 App 中，以模擬的限流、權限不足、磁碟已滿與檢查中四種工作逐一檢查畫面。
