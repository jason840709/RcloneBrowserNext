# 活動檔案為什麼會重複傳輸

## 增量比較的單位是檔案

rclone 先依選定方式比較來源與目標，略過無需更新的檔案。需要更新時，通常會傳送整個檔案；它不把大型紀錄檔增加的幾 KB 自動轉成僅傳幾 KB 的區塊差分。因此，一個 700 MB 紀錄檔只增加少量文字，也可能再傳一次整個檔案。

來源若在複製過程中持續增長，複製前記錄的大小與複製後的目標大小會不同，rclone 的驗證便會報錯。預設工作嘗試次數為 3，包含首次；同一檔案可以被傳送三次而仍未取得穩定副本。進度的累計處理量會包含這些嘗試，不能據此判定新增加了同樣容量的內容。

來源：[rclone FAQ：partial transfers / binary diffs](https://rclone.org/faq/#why-doesnt-rclone-support-partial-transfers-binary-diffs-like-rsync)、[工作嘗試次數](https://rclone.org/docs/#retries-int)。

## 備份執行中的程式資料夾

要保存完整且一致的資料夾，先正常結束會寫入它的程式，再執行備份；需要不中斷服務時，應使用檔案系統快照或應用程式提供的備份方式。直接讀取仍在更新的資料庫及日誌，可能在同一輪拿到不同時間點的檔案。

SQLite 資料庫可由其 Online Backup API 或 `VACUUM INTO` 建立快照；這是資料庫的備份工作，rclone 的一般複製不會自動替應用程式執行。[SQLite 官方備份文件](https://www.sqlite.org/backup.html)

如果目前只是想先複製穩定檔案，可將「工作嘗試次數」設為 1，減少同一輪反覆讀取大型活動檔案；等來源停止寫入後再執行一次。這個選項改變重試次數，實際失敗仍會記錄。

## 如何閱讀 0.7.0 報告

- 「成功複製大小」累計有大小資料的成功複製事件。重試間再次變動並成功複製的同一路徑會再次計入。
- 「失敗副本大小」累計大小驗證錯誤所提供的目標副本大小。其他類型錯誤沒有提供副本大小時，不會猜測流量。
- 比對結果、成功動作、檔案錯誤與工作重試摘要分開列出。一次檔案失敗及其工作摘要是同一輪的不同紀錄，不能當成兩個不同檔案失敗。
- 報告新增工作設定快照，包含比對、篩選、連結處理與工作嘗試次數。這些資料用於說明 rclone 這一輪實際採用的條件。

以上是 rclone 事件的邏輯大小。伺服器端複製、本機檔案系統複製與網路傳輸使用不同資料路徑，報告不將邏輯大小標示為網卡流量。

## 符號連結與特殊檔案

符號連結保存另一個路徑；socket 是程式通訊端點，不是可複製的一般內容。rclone 預設略過這些項目，略過通知本身不等於一般檔案複製失敗。

「保留符號連結」使用 `--links`，保存連結及其指向路徑，雲端以 `.rclonelink` 表示。選相同選項下載可還原連結。指向備份範圍外的內容需另外備份；本功能不跟隨連結擴大範圍。[rclone 連結處理](https://rclone.org/local/#local-links-links-l)
