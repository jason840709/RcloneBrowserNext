# Rclone Browser Next 介面設計規範

這份文件規定 Mac 版介面的比例、字級、顏色、元件造型、間距與動畫。所有數值都定義在 `WebSource/renderer/styles/tokens.css`，其他樣式檔只能引用那裡的變數；原生工具列（`Sources/Mac/MainToolbar.swift`）使用相同的時間與曲線。改介面前先讀這份文件；要新增規則，先改這份文件和變數檔，再改元件。

設計參考：macOS 的 Finder 與系統設定、Apple 的 Human Interface Guidelines。skill 只用來查常見做法，採用與否以本文件為準，同一類元件不混用兩套規則。

## 1. 比例

本文件的「點」是 macOS 的長度單位（point），Finder、系統設定的字級和圖示大小都用它計算；在一般螢幕上 1 點約等於 1 個實體像素，Retina 螢幕上等於 2 個。介面大小 100% 時，網頁的 1 個像素等於 macOS 的 1 點（WebKit 縮放 1.0）。所以樣式裡寫 13px，畫面上就是 13 點，和 Finder 用同一把尺。設定裡的 80%～125% 直接等於縮放倍數。

對照 Finder 清單（文字 13 點、圖示 16 點）：

| 項目 | 數值 |
|---|---|
| 清單文字 | 13 點 |
| 清單圖示（資料夾、檔案） | 16 點 |
| 清單列高 | 22 點（Finder 約 20 點；多 2 點給勾選框） |
| 欄位標題 | 11 點 |
| 勾選框 | 14 點 |

清單用虛擬捲動，`BrowserPane.tsx` 的 `fixedItemHeight` 必須等於 `--row-h`，兩者不一致會讓捲動位置算錯。窄窗格的收合規則用容器查詢，容器只能設在窗格上方的工具列（`.pane-header`），不能設在整個窗格：WebKit 會因此算錯清單的可見範圍，捲到底時往上彈（0.10.0 的錯誤）。

## 2. 字級

每一種用途只有一種字級、字重和顏色。標題永遠不小於它底下的內容。

| 用途 | 變數 | 字級／字重 | 顏色 |
|---|---|---|---|
| 頁面標題（傳輸、作業） | `--fs-display` | 17／700 | 主要文字 |
| 對話框標題 | `--fs-title` | 15／600 | 主要文字 |
| 區塊標題（設定的分組） | `--fs-heading` | 13／600 | 主要文字 |
| 內文、清單、按鈕、表單值 | `--fs-body` | 13／400 | 主要文字 |
| 控制項下方的說明、數據 | `--fs-callout` | 12／400 | 次要文字 |
| 小分組標籤、欄位標題 | `--fs-label` | 11／600 或 500 | 次要文字 |
| 狀態列、時間 | `--fs-caption` | 11／400 | 次要文字 |
| 徽章數字 | `--fs-mini` | 10／600 | 依底色 |
| 路徑、指令、紀錄 | `--fs-mono` | 12，等寬字 | 次要文字 |

文字顏色只有四層：主要（`--label`）、次要（`--secondary`）、第三層（`--tertiary`，只給圖示與非必要資訊）、停用。

## 3. 顏色與強調色

整體是中性灰，強調色只出現在下列地方，所以換主題時一眼看得出差別，但不會到處都是顏色：

| 位置 | 變數 |
|---|---|
| 主要按鈕、勾選框與單選、進度條、數量徽章、選單的反白 | `--accent` |
| 資料夾圖示 | `--folder` |
| 使用中窗格的選取列（強調色混入窗格底色） | `--selection` |
| 連結、文字按鈕、選取中分段或分頁的圖示、「來源」標籤、作業圖示、焦點光暈 | `--accent-text` |

強調色是從 App 圖示取的低彩度紫、綠、藍，不使用高彩度的系統色。語意色（綠＝完成、紅＝錯誤、橘＝注意）只用在狀態，不拿來裝飾。正常的等待階段（rclone 在比對檔案、或在等雲端確認收到檔案）不把速度換成一段文字：速度數字照常顯示、改用次要文字色，後面加一個和資料夾載入相同的小轉圈，說明放在滑鼠提示裡；不用橘色，避免被讀成警告。滑鼠提示掛在整個項目上（名稱、數字和到下一個項目之前的空白），不只掛在幾個字上。原生工具列只在兩處用強調色：選取中頁面的圖示、傳輸數量；視窗不在作用中時由系統改成灰色，和 Finder 一樣。工具列按鈕沒有圓形外框：介面照 macOS 15 的樣子設計，建置時在主程式記錄 SDK 15.0（`Scripts/common-mac.sh` 的 `RBN_DESIGN_SDK`）。用 macOS 26 以後的 SDK 直接編譯時，系統會在每個工具列按鈕外加玻璃圓圈（2026-11-07 的 0.10.2 本機建置就是這樣），`verify-mac.sh` 會擋下這種 App。

## 4. 元件造型與層級

形狀和深度表示元件的類型，不靠顏色區分：

| 元件 | 造型 |
|---|---|
| 按鈕、彈出選單按鈕 | 膠囊形、往外凸（填色＋陰影），高 26 點；主要按鈕用強調色 |
| 輸入框、搜尋框、網址列 | 6 點圓角矩形、往內凹（內陰影＋細框），高 24 點 |
| 分段控制、分頁 | 往內凹的膠囊軌道，只有一個往外凸的滑塊；未選取的段落沒有底色，相鄰的未選取段落之間用短細線分隔 |
| 圖示按鈕 | 平常無底色，滑過時出現圓形底 |
| 設定的分組框 | 10 點圓角，標題放在框外 |
| 對話框 | 16 點圓角 |

有前後關係的控制項合成一個元件：位置選單＋路徑＋瀏覽按鈕是同一條網址列（左邊是位置，細線分隔，右邊是路徑），不拆成三個獨立元件。

## 5. 間距

以 4 點為單位：4、8、12、16、20、24、32（`--sp-1`～`--sp-8`）。

分組的規則是「離自己近、離別人遠」：設定的區塊標題離自己的框 8 點，離上一個框 21 點。對話框內距左右 20 點，頁尾按鈕間距 8 點。

## 6. 動畫

全 App 只有一套動畫規則：

- 進入用減速曲線（`--ease-out`）或滑動曲線（`--ease-glide`）；離開的時間約為進入的三分之二。
- 不回彈、不超過終點。
- 只動位移、縮放、透明度和顏色。
- 動畫進行中隨時可以再點，不鎖住操作。

| 互動 | 動畫 | 時間 |
|---|---|---|
| 滑過、顏色變化 | 漸變 | 120 毫秒 |
| 按下按鈕 | 縮到 97%，放開回彈 | 100～160 毫秒 |
| 分段控制、分頁、頂部頁面切換 | 滑塊滑到選取項，文字與圖示顏色同步漸變 | 280 毫秒 |
| 切換傳輸方向 | 原來源側的勾選框縮小淡出、欄位收起；新來源側欄位展開、勾選框放大浮現 | 約 450 毫秒（分段） |
| 切換頁面（檔案、傳輸、作業） | 新頁從所選方向滑入 16 點並淡入；App 開啟時第一頁不動 | 300 毫秒 |
| 設定與選項的分頁內容 | 依方向滑入 14 點並淡入；視窗剛打開時不動 | 300 毫秒 |
| 對話框 | 開啟：背景暗幕淡入，對話框上移 10 點並從 96% 放大；關閉：淡出並略為下沉 | 開 260、關 180 毫秒 |
| 選單、彈出視窗 | 從觸發點放大並淡入；關閉淡出 | 開 200、關 120 毫秒 |
| 說明提示 | 停留 0.4 秒後淡入（原生工具列的提示同樣是 0.4 秒） | 160 毫秒 |
| 展開更多選項 | 箭頭旋轉，內容下滑淡入 | 240 毫秒 |
| 傳輸佇列收合 | 高度與箭頭一起變化，內容淡出 | 240 毫秒 |
| 新的傳輸工作 | 從上方滑入 | 260 毫秒 |
| 提示訊息（含「設定已儲存」） | 從下方升起並淡入，幾秒後自動收起，不佔版面 | 260 毫秒 |
| 切換主題 | 整個畫面交叉淡化 | 280 毫秒 |
| 問題燈號（工作進行中） | 透明度在 100% 與 35% 之間緩慢起伏，表示「請看一下」；工作結束後停止 | 每次 2.4 秒 |

系統開啟「減少動態效果」時：位移、縮放、回彈全部改成 140 毫秒的淡入淡出，問題燈號不閃；讀取中的轉圈照常轉，因為停住的轉圈看起來像當機。

## 7. 對話框的關閉方式

- 點對話框外的暗色區域會關閉對話框，效果等於按「取消」或「關閉」。
- Mac 版的工具列也會一起變暗，點那裡同樣會關閉。
- 對話框裡有尚未套用的修改時，點暗色區域不會關閉，對話框會輕輕彈一下，避免誤點丟掉修改。
- 對話框打開時，工具列不切換成停用狀態，避免按鈕閃一下暗一下亮。

## 8. 傳輸中的問題提示

錯誤不直接把 rclone 的原文攤在畫面上。每個工作最多一行提示：一顆 7 點的小燈，加一句白話標題；完整說明、要怎麼處理、rclone 的原始訊息都收在「說明」裡。

| 等級 | 什麼情況 | 燈 | 說明 |
|---|---|---|---|
| 注意 | rclone 會自己處理：限流、網路不穩、雲端暫時出錯、會重試的錯誤 | 橘（`--orange-fill`），進行中會閃 | 收起 |
| 需要處理 | 使用者要做點什麼，但工作還能繼續：沒有權限、檔名太長；或工作失敗 | 紅（`--red`） | 收起 |
| 緊急 | 整個工作無法繼續：雲端空間已滿、目標磁碟已滿、帳號登入過期 | 紅 | 出現時自動展開一次 |

- 白話標題與說明由 `renderer/errorExplain.ts` 依錯誤訊息辨認；認不出的錯誤用通用標題，原文照樣收在說明裡。
- 工作成功結束代表錯誤已在重試後解決：不顯示燈號，錯誤次數改用次要文字色。
- 燈號的顏色與錯誤數的顏色一致；「詳細資料與紀錄」旁的錯誤數在「注意」等級用橘色。

## 9. 檢查方式

- 動畫要用開發版的連續擷取逐格檢查（見 `03_開發資料/0.10.0_開發工具` 的 `dev.sh burst`），不能只看靜態截圖。
- 尺寸要和 Finder 的截圖比對實際像素。
- 自動化測試 `tests/revision10-motion.spec.ts` 固定了點背景關閉、修改保護、滑塊位置、首頁不滑入與提示延遲。
